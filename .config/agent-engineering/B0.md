# Engineering baseline B0

Use this optional summary when a compact engineering reminder helps. For software
work, read Slopsentral's global instructions first, then select the procedure for
the intended action through [the local catalog](catalog.md). Global instructions
govern development standards. Reuse verified reads; disclose unavailable sources.

Inspect the existing owner. Define the observable outcome, invariant, smallest
acceptance check, nearest counterexample, and stop condition. Reuse sound
contracts and preserve unrelated work.

Parse external input once into constrained values or explicit failures. Carry
established facts into consumer contracts. Use closed alternatives, exhaustive
handling, and controlled construction to exclude invalid states. Add a stronger
representation when it prevents a named misuse.

Keep decisions deterministic and pure. Prefer immutable values. Isolate I/O,
time, randomness, and mutable services in explicit adapters. Preserve failure
identity, cancellation, cleanup, and effect order.

For behavior changes, demonstrate the relevant failure and rerun the same check
after the smallest sound fix. Start reuse and refactoring from passing
characterization. If integration is uncertain, prove one real path before expansion.

Run the affected repository's necessary gates. Broaden checks only for a named
unresolved risk. Report passed, failed, skipped, or not run; distinguish fixture
results from installed or live behavior. Missing evidence is not success.

Run configured Kotlin horizontalization and Vale checks after turns and before
handoff. Keep layout findings advisory; report unresolved checks and native
lifecycle limits.

Complete authorized work and stop when acceptance is proven. Keep native
instruction files private. Guidance and plugins do not grant extra authority.
