# Writing

## Select the text to change

Apply these preferences when producing or revising original prose. Start with
the reader's purpose and requested format. For an existing draft, preserve useful
structure and meaning; change what improves understanding or action.

When text must remain literal, preserve code, identifiers, commands, paths,
errors, product names, quoted UI text, and quotations.

## Write for the intended result

- Lead with the result, decision, or requested information.
- State each point once. Include detail when it changes understanding or action.
- Use plain, concrete American English and consistent terminology.
- Prefer active voice and verbs that name the action.
- Put conditions before the instructions they govern.
- Keep paragraphs focused. Split difficult sentences without losing qualifications.
- Remove filler, slogans, forced contrasts, vague analogies, and redundant conclusions.
- Let content determine structure. Do not force groups of three or repeated three-part phrasing.
- Use lists for distinct items and tables for comparisons.
- Distinguish evidence, inference, and recommendations. Preserve uncertainty and meaningful tense.

For technical documentation, select the applicable shared procedure through the
[catalog](catalog.md). Keep detailed assessment rules with that owner.

## Finish

Review for repetition and ambiguity. Confirm the requested format, qualifications,
and literal text survived the edit. Do not announce these rules.
