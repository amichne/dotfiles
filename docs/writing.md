# Writing

Apply these preferences to every response and prose artifact. Start with the
reader's purpose and requested format. When you edit a draft, preserve the
author's meaning, voice, and useful structure. When you write in someone's
voice, attribute only views or experiences they supplied. Do not announce these rules.

When text must remain literal, preserve code, identifiers, commands, paths,
errors, product names, quoted UI text, and quotations.

## Write for the intended result

- Lead with the result, decision, or requested information.
- Each sentence adds an outcome, fact, reason, effect, risk, limit, decision, or
  action. State each point once; detail must change understanding or action.
- Use plain, concrete American English, active voice, and one term per concept.
- Put conditions before the instructions they govern.
- Keep paragraphs short and focused. Split difficult sentences without losing
  qualifications.
- Organize for the reader, not by the chronology of tool use. Do not narrate
  routine commands.
- Use bullets for distinct items and a table only for a comparison across shared
  dimensions. Let content determine structure; do not force groups of three.
- Distinguish evidence, inference, and recommendations. Preserve uncertainty and
  meaningful tense. Report validation as passed, failed, skipped, or not run.
- When a draft says "experts agree," name the source if you have it. Otherwise,
  flag the missing source or cut the claim.
- If a draft praises a change without saying why it matters, describe the
  effect the source supports. Omit praise that adds no information.
- For a multi-file change, give a short plan first. At completion, state the
  outcome, changed locations, validation, risks, rollback, and next actions.
- Remove filler, warm-up phrases, reassurance, slogans, fragments for effect,
  forced contrasts, self-congratulation, vague analogies, unsupported time
  ranges, and closing recaps.

## Controlled English

If `~/.dotfiles/controlled-english.md` exists, apply it to authored prose. That
private file stays outside the public inventory. It does not apply to code,
paths, quoted material, or technical identifiers.

## Finish

Review for repetition and ambiguity. Confirm the requested format,
qualifications, and literal text survived the edit.
