# Engineering baseline

Keep personal guidance at its existing HOME-relative owner,
`.config/agent-engineering`. Dotfiles distributes these ordinary source files.
Native instruction loading needs its own evidence.

| File | Responsibility |
| --- | --- |
| `catalog.md` | Select personal guidance and reach the shared task catalog |
| `writing.md` | Personal preferences for original prose |
| `B0.md` | Optional compact engineering reminder, below 250 words |

## Select the intended work

For software work, read Slopsentral's
[global instructions](https://raw.githubusercontent.com/amichne/slopsentral/refs/heads/main/docs/public/reference/global-instructions.mdx)
first, then use its
[task catalog](https://raw.githubusercontent.com/amichne/slopsentral/refs/heads/main/docs/public/reference/catalog.mdx)
to select the procedure before the action it governs. Read detailed references
when their conditions apply. Reuse verified reads at a consistent revision and
reconsider the selection when the intended action changes.

Keep Python tooling, invariant design, type safety, effects, and failure contracts
under their Slopsentral owners. The personal catalog does not maintain a second
index of shared skills. Use each repository's necessary checks; dotfiles uses
`./scripts/check.sh`.

For source review or a ZIP and patch, inspect the verified source owner and
produce the requested source result. A missing live HOME destination does not
block that work. For native integration, inspect the installed owner as follows.

## Connect native instructions

Native instructions and hooks remain private. Keep each project's rules in its
own scope. Preserve the installer's rejection of a tracked HOME-root `AGENTS.md`.

1. Inspect the actual Git directory, worktree, origin, revision, and scoped status.
2. Inspect the active native instruction file and the producer that manages or
   verifies it. For Codex, check `CODEX_HOME` and `AGENTS.override.md` before
   choosing the file. The default global location is `~/.codex/AGENTS.md`.
3. Merge the applicable reference block through that owner. Preserve private
   content and existing task, permission, and handoff preferences.
4. If a producer verifies a digest or snapshot, use its established update and
   verification flow. A direct edit that invalidates its receipt is incomplete.

Other harnesses have their own discovery rules. See the
[official Codex AGENTS.md guide](https://developers.openai.com/codex/guides/agents-md).
Do not copy a supplied files directory wholesale over HOME.

```markdown
## Personal guidance

Resolve these paths against the current user's HOME, not the project directory.
Before producing or revising original prose, read
`$HOME/.config/agent-engineering/writing.md`. Preserve requested formats and
literal text.

For software work, read Slopsentral's
[global instructions](https://raw.githubusercontent.com/amichne/slopsentral/refs/heads/main/docs/public/reference/global-instructions.mdx)
first. Then use `$HOME/.config/agent-engineering/catalog.md` to select the
procedure for the intended action. Open detailed references when their
conditions apply. Reuse verified reads at a consistent revision and reconsider
the selection when the action changes.

If a required file or source is unavailable, name the precise gap and complete
independent authorized work without claiming compliance.
```

This block gives explicit reading instructions. Markdown links alone do not
establish that a harness loaded a file.

## Verify the selected outcome

For a source package, verify clean patch application, resulting bytes and modes,
local links, the public inventory, the existing B0 assertion, the documentation
build, and the required repository gate. Report missing dependencies explicitly.

For native integration, start a fresh harness session and inspect available
instruction-loading evidence and actual reference reads. Check the relevant
branch: original prose, software work, or a change of intended action. File
existence and unsupported model self-report do not establish loading or compliance.
If the harness exposes insufficient evidence, name that gap.

Stop when the requested outcome is verified. Keep source checks, installed-file
checks, and observed native reads distinct in the report.

## Preserve meaning when editing prose

Keep uncertainty, meaningful tense, exact technical strings, and quotations.
Let content determine structure; a legitimate three-item list is acceptable.
Sentence length is a review signal. For technical documentation assessment,
select the applicable shared procedure and review its findings against the facts.
